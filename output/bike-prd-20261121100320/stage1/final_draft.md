# 骑行记录功能产品文档（纯手机版）

## 一、文档概述

### 1.1 背景与目标

当前应用是一款基于 Flutter 的纯离线电助力自行车码表，核心能力集中在实时显示（速度、里程、均速、极速、电量、温度、倾角）与蓝牙助力控制（含 BR80 闪控）。但数据仅在本次连接期间存在，断线或重启即清零，不具备任何"记录"能力。

对标 Strava、行者等主流骑行应用后，本次立项为应用补齐骑行数据记录闭环。目标是在**不依赖任何外接传感器、不联网、不登录**的前提下，让手机独立完成"记录—存储—分析—导航"的完整链路，覆盖成熟骑行应用约 60% 至 70% 的核心价值。

### 1.2 范围界定

本期只实现"仅靠手机硬件即可完成"的能力。手机可直接获得 GPS 定位、加速度计、本地存储与网络（可选）；由此可采集轨迹、速度、距离、时长、海拔，并经算法衍生出爬升、坡度、卡路里、估算功率等指标。

心率带、踏频器、功率计、胎压传感器等外接设备所提供的数据，手机硬件无法测量，本期**不实现，仅在数据模型中预留字段**作为后期扩展。现有电机控制器与 BR80 闪控的蓝牙连接属于项目本体，不在本次排除范围内。

### 1.3 名词说明

| 名词 | 说明 |
|------|------|
| 轨迹点 | 一次定位采样得到的经纬度、高程、速度、时间戳记录 |
| 路书 | 预先规划或由历史轨迹生成的有序路径点集合，用于导航跟随 |
| PB | Personal Best，个人最佳成绩 |
| GCJ-02 | 国内合规地图采用的坐标系；WGS-84 为 GPS 原始坐标系 |

## 二、产品定位与用户场景

### 2.1 定位

一款"随身骑行记录仪 + 本地分析台"：安装即用、无需账号、完全离线、数据只存本机。它不追求 Strava 式的社交网络，而是把个人骑行数据完整、准确地沉淀下来。

### 2.2 核心用户场景

1. **日常通勤与训练**：打开应用即开始记录，骑完暂停保存，随时回看本次的距离、均速、爬升与轨迹。
2. **长途骑行复盘**：按周/月/年查看里程统计与日历热力图，对比同一路线的历史成绩。
3. **陌生路线跟随**：提前载入路书，骑行中沿轨迹引导，显示进度、剩余距离与偏航提醒，无需实时联网算路。
4. **数据交换**：将骑行导出为 GPX 分享，或从外部导入 GPX 统一管理。

### 2.3 双模式形态（按连接状态切分）

应用以"是否连接助力器（电机控制器 / BR80 闪控）"为分水岭，在两种界面形态间切换，二者共用同一套 GPS 测速与里程内核。

**纯码表模式（未连接助力器）**：此时应用就是一台独立的骑行记录码表，面向没有助力器的普通骑行者，也是本期记录功能的主场。保留速度表盘/数码管、均速/极速/里程、骑行时间等 GPS 可驱动的信息；隐藏助力控制卡片（模式、百分比滑杆、加减键）、电量/温度/陀螺仪传感器行（其数据源本就来自控制器，未连接时并无实际数据）、以及设备页之外的助力相关设置项（重启设备、陀螺仪校准与自动读取、爬坡参数、蓝牙调试等）。腾出的空间留给骑行记录控制条与轨迹/坡度显示。演示模式在该形态下只演示速度，不再填充助力假数据。

**助力完整模式（已连接助力器）**：保留现有全部能力，含助力控制卡片、传感器行、设备页与全部设置项；骑行记录相关功能在此模式下同样可用。

**切换机制**：默认自动——连接建立即进入完整模式，连接断开即退回纯码表模式；同时在设置中提供"锁定纯码表模式"开关，手动锁定后即使已连接助力器也隐藏全部助力界面，供只想记录数据的用户使用。两种模式的切换不改变已经采集的骑行数据，记录不中断。

**连接入口**：纯码表模式保留底部"设备"标签但弱化其视觉权重，未连接时语义呈现为"连接助力器"，确保用户随时可以进入完整模式。设备页本身不隐藏，避免形成无法连接、无法回到完整模式的死路。

## 三、功能范围

### 3.1 功能全景与覆盖状态

成熟骑行应用可归纳为六大模块。下表标注当前码表的覆盖情况。

| 模块 | 典型能力 | 当前状态 |
|------|---------|---------|
| 实时记录与显示 | 速度/里程/均速/极速、骑行时间、电量/温度/倾角 | 已具备 |
| 实时记录与显示 | 心率/踏频/功率、GPS 轨迹与累计爬升 | 本期补齐轨迹与爬升 |
| 数据记录与管理 | 单次汇总与保存、历史归档、生涯统计、GPX、多设备云同步 | 本期补齐前四项，不做云同步 |
| 分析与复盘 | 速度/海拔曲线、功率/心率区间、分段与 PB | 本期补齐曲线与 PB |
| 路线与导航 | 路书规划、离线导航、热门路线/热力图 | 本期做轻量路书跟随 |
| 竞赛与社交 | 路段排行榜、挑战勋章、俱乐部组队 | 不做 |

### 3.2 本期能力链路

功能按"数据从哪来、如何加工、如何落地"分为四层，全部在手机本地完成：

1. **手机原生能力**：GPS 定位、加速度计、本地存储；网络仅作为可选增强。
2. **直接采集**：轨迹点、速度与距离、海拔、时长与运动状态。
3. **算法衍生**：累计爬升与坡度（高程差分加滤波）、分段与 PB、卡路里（体重加 MET 模型）、估算功率（速度、坡度与风阻模型）。
4. **落地功能**：骑行记录与汇总、历史与轨迹回放、速度/海拔分析图表、路书导航与 GPX 交换。

### 3.3 明确不做

云同步与账号体系、社交/排行榜/组队、在线地图瓦片与热门路线、实时 turn-by-turn 算路、外接传感器接入。

## 四、功能需求详述

### 4.1 骑行记录

提供"开始 / 暂停 / 继续 / 结束"四态状态机。开始后按固定间隔采集 GPS 轨迹点并持久化；暂停时不记点、不计里程；结束时生成一次骑行汇总。汇总字段包括总时长、移动时长、总距离、移动均速、极速、累计爬升、最高海拔、起止时间与轨迹点数量。移动均速须排除停止时间，避免等红灯拉低数值。

要求后台持续记录，采用 Android 前台服务保活并显示常驻通知；对 GPS 漂移点（精度差、距离跳变、速度异常）做过滤，与现有 `GpsService` 的过滤策略保持一致。

### 4.2 本地历史与回放

以时间倒序列表展示历史骑行，每条显示日期、距离、时长、均速与轨迹缩略图。详情页在地图上回放完整轨迹，并叠加当前位置随时间移动的动画。列表支持按日期范围筛选与删除单条记录。

### 4.3 数据分析

详情页提供速度曲线与海拔剖面图，横轴为距离或时间。标注每公里分段（split）用时与速度；计算并展示 1 公里、5 公里等项目的最佳成绩。统计页给出周/月/年里程与次数、日历热力图，帮助用户观察训练节奏。

### 4.4 GPX 导入导出

支持将一次骑行导出为标准 GPX 文件（含轨迹点与时间、高程信息），便于外部浏览或备份；支持导入外部 GPX 并纳入本地历史统一管理。导入时需处理坐标系差异（见 5.5）。

### 4.5 路书导航

用户可将历史轨迹"另存为路书"，或导入外部 GPX 路书。导航过程中只做三件事：将当前位置投影到路线折线以计算进度与剩余距离；检测偏离路线并在超过阈值时提醒；接近关键点（路口、补给点）时给出提示。显示层呈现路线折线、当前位置与关键点标记。

## 五、关键技术方案

### 5.1 数据模型

核心实体建议为：`Ride`（一次骑行，含汇总字段与起止时间）、`TrackPoint`（轨迹点，含经纬度、高程、速度、时间戳、归属 Ride）、`Route`（路书，含名称与点序列）、`RiderProfile`（体重等用于卡路里估算的配置）。

现有 `BikeData` 已含 `assistPower`、`motorPower`、`temperature` 等字段，新增模型应确保心率、踏频、功率、胎压等字段有预留位置，便于后期外接设备接入而不改动表结构。

### 5.2 存储方案

结构化数据采用本地 SQLite（如 Drift 或 sqflite），GPX 以文件形式存于应用私有目录，`SharedPreferences` 保存用户配置。轨迹点数据量较大，建议按距离或时间做抽稀后再落库，以平衡精度与存储/性能开销。

### 5.3 前台服务与功耗

持续 GPS 采样是耗电主因。建议在保证轨迹质量的前提下合理设置采样间隔（如每秒一次或按距离触发），并在停止移动时降低采样频率。前台服务须处理 App 被系统回收后的恢复与断点续记。

### 5.4 路书导航方案选型

曾评估三条路线：其一，由外部导航应用回传精简数据——Android 无稳定公开通道，通知监听或无障碍方案脆弱且涉及敏感权限，予以排除；其二，应用内集成完整导航 SDK——体验完整但包体大、需联网算路、与离线定位相悖，留待后期；其三，应用内路书跟随导航——只做位置投影、偏航与进度，不需实时算路，可完全离线，复用现有 GPS 流与里程算法，与产品定位最契合。

**本期选择方案三，并采用自绘轨迹图**：用 `CustomPainter` 将坐标投影到屏幕，绘制路线折线、当前位置与关键点，不接入任何第三方地图 SDK，因此无需注册开发者、无需申请 key、无需联网。

架构上须将绘制层抽象为统一接口（如 `RouteMapRenderer`），导航状态机、偏航算法与进度计算只依赖该接口。将来若要升级为真实街道底图，只需替换绘制层实现，导航核心代码不变。

### 5.5 坐标与合规

自绘方案下坐标全程统一使用 GPS 原始的 WGS-84，不叠加第三方底图，故不存在坐标系偏移问题。若后期引入底图，须遵守国内地图数据合规要求：底图服务仅限腾讯地图（默认）、高德、百度、天地图等具备资质的厂商，禁用 Google、Mapbox、OpenStreetMap 海外瓦片等来源；同时须将 WGS-84 转换为 GCJ-02，否则会产生数百米偏移。地图 key 由使用者自行到对应开放平台申请，代码中不预置任何有效 key。

## 六、分期与里程碑

| 阶段 | 范围 | 交付价值 |
|------|------|---------|
| P0 核心闭环 | 骑行记录状态机、轨迹落库、前台服务、本地历史列表与轨迹回放、基础汇总 | 数据不再丢失，可回看每次骑行 |
| P1 分析与交换 | 速度/海拔曲线、分段与 PB、统计热力图、GPX 导入导出、卡路里与爬升 | 从"记录"升级为"复盘分析" |
| P2 路书导航 | 路书生成与导入、RouteMapRenderer 自绘、进度/偏航/关键点提示 | 离线跟随导航，补齐导航能力 |

P0 是后续一切能力的基础，应优先保证记录准确性与稳定性。P1、P2 可在 P0 稳定后并行推进。

## 七、风险与约束

1. **GPS 精度与耗电**：城市峡谷、树荫下精度下降，冷启动较慢；持续记录耗电明显。需通过过滤算法、采样策略与前台服务保活缓解，并在 UI 上如实提示定位状态。
2. **爬升精度**：仅靠 GPS 高程存在数米级抖动，须做阈值滤波避免虚增；若设备自带气压计可作为后期增强。
3. **数据安全**：骑行轨迹属于个人位置信息，仅保存在本机，不采集、不上传他人数据，符合个人信息保护要求。
4. **升级路径**：路书导航须在一开始就做好绘制层抽象，避免后期接底图时大规模返工。

## 八、验收标准（要点）

- 一次完整骑行可被正确记录并保存，重启应用后历史仍在；暂停期间不计里程。
- 汇总中的距离、均速、极速、爬升与原始轨迹一致，计算规则明确可复核。
- 轨迹地图可完整回放，速度/海拔曲线与轨迹时间戳对应。
- GPX 导出文件可被第三方软件正确打开，导入后数据进入本地历史。
- 路书导航可显示进度、剩余距离并在偏航时提醒；全程无需联网与第三方账号。
- 未连接助力器时进入纯码表模式：助力卡片、控制器传感器行与助力类设置项均隐藏，且不影响骑行记录；连接后自动恢复完整模式，断开后自动退回，手动锁定开关优先于连接状态。
- 全部功能在无网络、无登录状态下可用，个人数据仅存本机。
