# JSON 帧格式（来自 libapp.so 汇编，未经过设备实测）

> 原 App 还包含另一套以 `7E` 开头的旧版二进制协议；分支选择涉及扫描广播 serviceData 的 `2A04`，不能用 GATT 特征布局代替判断。详见 `原厂协议分析_2026-11-07.md`。

来源函数：`CommandJsonUtils.getCommand/getLength/getCrcCheckCode/getJsonObj`

## 发送帧

```
7F | len_lo | len_hi | JSON(ASCII, 无空格) | crc_lo | crc_hi
```

- `7F`：帧头（汇编里是 Smi 254，即 127）。
- `len`：JSON 字符串长度，**小端 2 字节**（`getLength`）。
- `crc`：CRC16-XMODEM（多项式 0x1021，初值 0），对 `7F + len + JSON` 全部字节计算，**小端**追加。
  - `crc = ((crc << 8) & 0xFFFF) ^ table[((crc >> 8) ^ b) & 0xFF]`
  - 表项在汇编里是 Smi（值×2），例如 `8258 = 0x2042` 实际是 `0x1021`。
- 接收长度上限 512（`parsingBackCommand`），首字节不是 `7F` 会丢弃。

## JSON 外壳

```
{"M":1,"S":0,"F":<功能码>,"D":{<key>:<value>}}
```

注意：汇编里整数是 Smi 编码（实际值×2），下面是换算后的值。

- 设置命令 `getSetCommand`：`F=1`，`D={"key":value}`。
- 查询命令 `getInquireCommandList`：`F=2`，`D={"key":null,...}`（可一次查多个 key）。
- 以上取值由汇编推出，**待实物验证**（抓包日志里只有握手，没有业务帧）。

## 文本控制命令（非 JSON）

`"@" + 内容 + "#"`，例如 `@NAME?#`、`@NAME=xxx#`、`@SRESET#`、`@UPGRATE=...#`。
回包以 `@OK` / `@ERROR#` 开头。

## GATT 特征（来自 BleManager.registerNotice）

主服务 `0000FFE0-0000-1000-8000-00805F9B34FB`，下挂 FFE1/FFE2/FFE3。
`newType` = 该服务同时含 FFE1、FFE2、FFE3 三个特征。

| 特征 | newType（新款） | 老款（只有 FFE1、FFE2） |
|------|----------------|--------------------------|
| FFE1 | c1 Write：写命令通道 | c2 read and write：读写，并 `notifyRead` |
| FFE2 | c1 read：`notifyRead` 订阅（回包） | c2 Control：`notifyControl` 订阅 |
| FFE3 | c1 Control：`notifyControl` 订阅 | 无 |

- 写入使用 `write(..., withoutResponse: ...)`：Android 一律 `true`；iOS 视 AppController 某个布尔值而定。
- 主设备另有服务 `FFD0`：特征 FFD1（设备服务）、FFD2（设备状态）、FFD3（踏频器/码表）。
- 设备信息服务 `180A`：2A29/2A24/2A25/2A27/2A28。`2ABE` 用于读设备名。
- DFU 服务：`FE59`（Nordic）。
- 以上角色是读汇编标签推断的，**未经实机验证**。
