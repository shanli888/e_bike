## 两套不同的业务协议

`Commands.getMainDate`（0x5abaa8）读取 `AppController` 的布尔状态，分别调用 `CommandsJson.getMainDate` 和旧版 `Commands.getMultipleCommand`。`Commands.getFirmwareVersion`（0x5b4734）也有相同分支。因此不应把 `7F` JSON 帧当作所有设备唯一协议。

原厂扫描回调（0x558520）把 `ScanResult.advertisementData` 的 serviceData 交给 `BleManager.isBluetooth5`（0x55f7c0）；该函数初始设为 false，遍历 serviceData 的 UUID，若包含 `2a04` 则设为 true。`connBle`（0x5604fc）把该结果赋给 AppController 的协议选择布尔值并保存 `isBluetooth5`。分支为 true 时调用 JSON，false 时调用旧版二进制。

**重要：这是广播 serviceData 的 UUID，不是连接后通用服务 1800 中的 GATT 特征 2A04。** 用户日志里有 GATT 2A04，不能据此认定广播中有该标记或协议分支。扫描结果可能被平台过滤或不完整，因此未发现也不能单独证明旧协议；需要实际广播记录与业务帧共同验证。

### JSON 分支

- `CommandJsonUtils.getInquireCommandList`（0x5ab084）生成 `{"M":1,"S":0,"F":2,"D":{"34":null}}` 形式的查询；`34` 在 `CommandsJson.getFirmwareVersion`（0x5b4950）中用于固件版本。
- `CommandJsonUtils.getCommand`（0x55659c）：`7F | JSON字节数(小端16位) | JSON | CRC16/XMODEM(小端16位)`；CRC 覆盖帧头、长度、JSON。
- `CommandsJson.getMainDate`（0x5aaaa0）查询键 `16,17,37,38,54,30,31,39,7,8,9,10`；需用真实回复确认各字段含义。

### 旧版二进制分支

- `CommandUtils.getInquireCommand`（0x5ab984）先生成 `[0C, ...keys]`，在首部插入 `keys数量 + 3`，对该内容计算 CRC16/XMODEM（初值 0），以**高字节在前**追加 CRC，最后在首部插入 `7E`。长度包括自身、功能码和 CRC，不包括帧头。
- 旧版 `Commands.getFirmwareVersion`（0x5b4734）查询单个键 `BB`；`Commands.getMainDate` 旧分支的键为 `BB C4 A0 A5 D2 D3 B1`。
- 与旧版不同，JSON 分支的 CRC 按低字节在前；不能混用。

## 原厂连接流程线索

- `BleManager.deviceConnSuccess`（0x5a8518）调用 `registerNotice`，随后启动 `runTimer`；后者启动命令队列和周期性查询。原 App 并不只是连接后被动等待通知。
- `registerNotice`（0x5c7468）按 FFE1/FFE2/FFE3 的组合选择通道并分别执行 `notifyRead`、`notifyControl`；具体分支仍需结合 AppController 状态和实机验证。
- `notifyRead` 回调（0x5cd5b4）检查 `XModeUtils` 或 `XModeUtils5`，遇到特定 XMode 数据时调用 `doSend`；是否为本车必需握手仍未确认。
- `writeControl`（0x5a9d9c）在 Android 分支使用无应答写。日志中 FFE1 无应答写已提交，只能证明本地写入操作成功，不能证明帧有效或设备执行。

- `LvBuHttpManage2.getOnlineCommandSilent`（0x5d4708）向手机侧的服务端接口 `app/AppOnlineCommand/GetOnlineCommandSilent` 发起 HTTP 请求；成功后由 `OnlineCommandUtils.runCommand`（0x5d4a00）处理服务端返回的命令列表。
- `OnlineCommandUtils.runCommand` 会依据服务端条目的 `set/get/control` 类型，构造 JSON 或文本控制命令并交给 BLE 写入路径。因此“online command”至少在这里指 App 向服务器获取下发任务，不能直接等同于设备 SIM 链路，也不能证明所有本地查询都依赖 SIM。
- `BleManager.runTimer` 同时包含本地 BLE 查询队列和服务端相关调用；静态调用关系能证明存在本地路径，但不能保证离线状态下这台设备的初始化、鉴权或所有功能无需服务端。
