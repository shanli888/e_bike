# 首页陀螺仪坡度显示逻辑

本文档描述首页「陀螺仪」卡片上那个角度数值与分段条是如何从设备取回、换算、并画到屏幕上的。覆盖真实设备链路与演示模式两条路径，以及无数据 / 0 附近 / 上坡 / 下坡四种显示状态。

代码位置：

| 环节 | 文件 |
|------|------|
| 命令定义与回包解析 | `lib/services/lvbu_read_only.dart` |
| 轮询调度与数据落地 | `lib/services/ble_service.dart` |
| 数据模型 | `lib/models/bike_data.dart` |
| 演示数据 | `lib/models/demo_ride_data.dart` |
| 首页 UI 与分段条 | `lib/screens/dashboard_screen.dart` |
| 专项测试 | `test/dashboard_screen_test.dart`、`test/lvbu_read_only_test.dart` |

## 一、整体链路

```
设备 BD 回包 → 帧解析（十进制换算） → BikeData.slope / gyroAngleAvailable
                                              │
                          ┌───────────────────┴────────────────────┐
                          │                                        │
                    首页陀螺仪卡                              设置页「陀螺仪角度」
                数值 1 位小数 + 11 格双向条                     数值 3 位小数（校准参考）
```

这个值来自**只读轮询**，不是蓝牙通知，也不是设置页那个查询按钮：

- 查询按钮走 `BleCommands.gyroQuery()`（老式 `AA 55 01 10 EF`），只反映命令执行结果，不承载角度值。
- `C6` 命令读的是**爬坡设定角**（`climbingAngle` / `climbingLevel`），是另一路独立数据，与这里的陀螺仪角度分开。

## 二、采集：BD 命令与轮询

### 2.1 命令定义

`lib/services/lvbu_read_only.dart` 的只读白名单中：

```dart
gyro('BD', '', 26, Duration(seconds: 30))
```

四个参数依次是：命令码 `BD`、后缀为空、应答帧长度 **26 个十六进制字符**（13 字节）、轮询间隔 **30 秒**。

请求帧按原厂格式拼装：`BD` + `F` + 15 位电机 IMEI，例如：

```
BDF123456789012345
```

经 `string2Hex` 转成字节后写入服务 `FFE0` 下的特征 `FFE1`（写 + 通知）。IMEI 是电机标识，不是手机 IMEI，属敏感数据，日志与文档中均不写出真实值。

### 2.2 轮询调度

`BleService._startLvbuReadOnlyPolling()` 启动 `LvbuReadOnlyPoller`：

- 轮询器每 1 秒 tick 一次，但每条命令按各自 `interval` 限频；BD 即 30 秒一次。
- 多条命令**串行**发送：同一时刻只有一条在途（`_busy` 标志，前一条结束才发下一条），且按「到期最久」排序。
- 发送前检查链路空闲（`_lvbuProbeRunning` / `_manualWriteRunning` / `_assistPriorityWrite` 等），手动调速与助力优先级写入会让只读查询让路。
- 单条查询：订阅 `FFE1` 通知 → 写请求 → 等回包，最长 **5 秒**；超时后再多等 2 秒隔离迟到回包，随后取消订阅并给回包保护置 10 秒冷却，避免与下一条命令串帧。
- 回包用独立 parser 按 `BD F<IMEI>` 前缀匹配，能隔离分片、错误设备和迟到回包。

### 2.3 数据新鲜度

`_applyLvbuReply()` 收到有效回包后记录成功时间到 `_lvbuLastSuccess`。另有一个看门狗：

- 若距离上次成功超过 **75 秒**，判定数据过期，清除成功记录并把 `gyroAngleAvailable` 置为 `false`。
- 断连时 `clearReadOnlyAvailability()` 同样清掉该标志，`_clearLvbuVoltage()` 会停止轮询器并清空成功/失败记录。

界面据此在「有数据」和「无数据（显示 `--`）」之间切换。

## 三、换算：回包里的 6 位十进制数

`LvbuReadReplyParser.feed()` 在拼齐 26 字符帧、确认前缀与设备标识后，取第 18–20 字符作为状态位，**只有 `01` 才继续解析**。`_parse()` 对 BD 的处理是：

```dart
if (command == LvbuReadCommand.gyro) {
  var n = decimal(frame.substring(20, 26));   // 第 20–26 位，6 位十进制数字
  if (n == null) return null;
  if (n >= 100000) n = 100000 - n;            // 负角度的偏移编码
  return LvbuReadReply(command: command, status: status, value: n / 1000.0);
}
```

要点：

1. **十进制，不是十六进制**：`decimal()` 用正则 `^\d+$` 校验，非纯数字整帧作废。
2. **6 位定长**：取 `substring(20, 26)`。
3. **负角偏移编码**：设备用 `100000` 作为零点偏移，`n ≥ 100000` 时表示负角度，做 `100000 − n` 还原成负值。
4. **缩放 1/1000**：结果以「度」为单位，精度到小数点后三位。

实测样例（`test/lvbu_read_only_test.dart`）：

```
回包尾部：01 113844
状态 01 → 有效；n = 113844 ≥ 100000 → 100000 − 113844 = −13844
角度 = −13844 / 1000 = −13.844°
```

解析结果在 `_applyLvbuReply()` 中落地：

```dart
case LvbuReadCommand.gyro:
  _bikeData.slope = reply.value!;
  _bikeData.gyroAngleAvailable = true;
```

模型注释明确写着「陀螺仪角度（度）；**并不一定等同于当前路面坡度**」——它是控制器姿态角，业务上当作坡度展示，但不要当成精确的路面坡度使用。

## 四、显示：首页陀螺仪卡

`DashboardScreen._buildSensorRow()` 取 `data.gyroAngleAvailable ? data.slope : null` 作为 `slope`：

- `slope == null`（无数据）：数值显示 `--`，分段条全灰。
- 有数据：数值 `slope.toStringAsFixed(1)`，显示 **1 位小数** 加单位 `°`。

注意设置页「陀螺仪角度」用的是 `toStringAsFixed(3)`（3 位小数），用于精确观察与校准；两处精度不同是有意为之。

### 4.1 双向分段条

陀螺仪卡不再用温度/电量那种 10 格单向条，而是专门的 **11 格双向条**（`_buildSlopeBar`）：

- 中心格索引为 **5**（0–10 共 11 格），左右各 5 格，因此存在唯一的中心格。
- 单侧亮起的格数 `level = (slope.abs() / 5).round().clamp(0, 5)`，即每格约 5°，单侧最多 5 格。
- 方向 `side`：`slope < 0` 为 −1（下坡，向左），`slope > 0` 为 +1（上坡，向右），`slope == 0` 为 0。

配置用 `SlopeBar` 值对象传递：

```dart
class SlopeBar {
  const SlopeBar({required this.hasData, this.side = 0, this.level = 0});
  final bool hasData;
  final int side;   // -1 下坡 / 0 平路 / 1 上坡
  final int level;  // 单侧亮格数 0~5
}
```

### 4.2 四种显示状态与配色

| 状态 | 判定 | 中心格（索引 5） | 左侧格 | 右侧格 |
|------|------|------------------|--------|--------|
| 无数据 | `hasData == false` | 灰 | 灰 | 灰 |
| 0 附近 | `level == 0` | **蓝** | 灰 | 灰 |
| 下坡 | `side == -1 && level > 0` | **绿** | 中心左侧 `level` 格绿 | 灰 |
| 上坡 | `side == 1 && level > 0` | **红** | 灰 | 中心右侧 `level` 格红 |

配色取自 `DashColors`：蓝 `#4AA8FF`、绿 `#3DDC8C`、红 `#FFFF0000`。熄灭格为 `Colors.white` 9% 透明度；亮格带同色辉光（`BoxShadow`）。

关键实现（`_buildSlopeBar`）：

```dart
final directionColor = bar.side < 0 ? DashColors.green : DashColors.red;
final isCenter = i == center;                       // center = 5
final filled = bar.hasData &&
    (isCenter ||
     (bar.side < 0 && i >= center - bar.level && i < center) ||
     (bar.side > 0 && i > center && i <= center + bar.level));
// 0 附近（level==0）只有中心格亮蓝；有坡度时中心格跟随方向色，整条同色。
final color = !filled
    ? idle
    : (bar.level == 0 ? DashColors.blue : directionColor);
```

**易错点**：平路必须按 `level == 0` 判定，不能用 `side == 0`。因为像 `0.4°` 这类 0 附近的值方向是 `side = 1`（上坡）、但 `level = 0`，若用 side 判定中心格会误变成红色。该场景已写入专项测试。

## 五、演示模式

未连接设备且打开演示开关时，首页数据由 `DemoRideData` 提供。坡度**随时间循环变化**，便于直接观察双向条的三种状态：

```dart
static const double slopeAmplitude = 25.0;   // 演示坡度幅值

/// −25°→+25°→−25° 匀速往返，与电量同周期（24 秒）但错开 1/2 相位。
static double slopeAt(DateTime now) =>
    -slopeAmplitude +
    2 * slopeAmplitude * _triangle(_phase(now, sensorCycleSeconds / 2));
```

`DemoRideData.bikeData(t)` 把 `slopeAt(t)` 与 `gyroAngleAvailable = true` 填入，走与真实数据**完全相同**的显示逻辑。首页在演示模式下每 500ms 按当前时间取一组值重建，因此坡度会匀速扫过 −25°～+25°：

- 负半周：显示下坡，中心与左侧格按 `level = round(|slope|/5)` 填绿，最多 5 格满格；
- 过零点：进入 `level == 0`，只亮中心蓝格；
- 正半周：显示上坡，中心与右侧格填红，最多 5 格满格。

一轮 24 秒依次走完「下坡满格绿 → 平路蓝 → 上坡满格红 → 平路蓝」。速度、电压、温度、坡度这几条曲线都随时间起伏，可在不连接设备的情况下预览所有配色与填充方向。

## 六、测试覆盖

`test/dashboard_screen_test.dart` 的专项用例「陀螺仪双向条：中心跟随方向色、下坡绿、上坡红、平路仅中心亮」通过给每个格子加 `ValueKey('slope-segment-$i')` 直接读取 `BoxDecoration.color` 断言：

- 无数据：11 格全灰；
- 下坡 −12°（`level=2`）：中心与左侧 3、4 格绿，右侧不填充；
- 上坡 +12°（`level=2`）：中心与右侧 6、7 格红，左侧不填充；
- 平路 0.4°（`level=0`）：仅中心蓝格亮，其余全灰。

`test/demo_mode_test.dart` 覆盖演示坡度循环：`slopeAt` 一个周期后首尾相接、幅值扫到 ±25° 两端、一轮内出现下坡/平路/上坡三态，且相邻两秒取值不同（动态刷新）。

`test/lvbu_read_only_test.dart` 覆盖回包解析：`gyro` 尾部 `01113844` 解析为 `−13.844`，以及分片、错误设备、非 `01` 状态的隔离。

## 七、一句话总结

设备每 30 秒通过 `BD` 帧上报一个以 `100000` 为零点偏移、放大 1000 倍的十进制角度；parser 校验帧后还原正负并除以 1000，存入 `BikeData.slope`；首页把它显示成 1 位小数，并用 11 格双向条表达——0 附近只亮中心蓝格，下坡中心与左侧亮绿，上坡中心与右侧亮红。
